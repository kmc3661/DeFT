# Implementation details

## Token budget

For `N` native visual tokens after the backbone's merger/projector, target pruning
fraction `p`, and reserve fraction `alpha`:

```
K = max(1, round(N * (1-p)))
M = min(N, K + ceil(alpha * (N-K)))
```

Python/PyTorch-compatible rounding and ceiling are important at small budgets.
At p80 and alpha=.2, approximately 36% of the original tokens enter the decoder,
then 20% remain after the midpoint. At alpha=.3, the initial fraction is 44%,
not 30%. Alpha is a fraction of the tokens that immediate top-K would discard.
The interface accepts [0,1]; [0.1,0.3] is the recommended study range, not a
mathematical constraint. The initial public release evaluates default=.2.

## Stage 1

Rank visual tokens using the encoder-derived scores used in the paper.
Qwen uses received visual attention, aligned with the native merged token grid.
LLaVA-OV uses the CLS-attention-only ranking from the penultimate vision block.
Stable descending argsort retains M candidates. No diversity selection or merge
is active. Remaining tokens preserve their original positions and sequence order.

## Stage 2

After 18 of the 36 decoder blocks, the selector uses active nonvisual query rows
and visual key columns of native decoder attention. Heads are averaged and
query contributions aggregated. Softmax is over **all visible keys**, not only
visual keys. Native causal masking remains in force.

The evaluated backend divides received mass by uniform-attention causal
exposure. For visual candidates with identical visibility this denominator is
constant and does not change top-K ranking. This normalization is **not PMI**
and does not use encoder image scores. The adapter prevents both encoder-prior
and PMI inputs to final selection, and optional runtime assertions verify this.

Keep K candidates using the backend's torch.topk tie behavior. Physically compact
the sequence after that block. There is no token restoration, merging, learned
scoring module, or iterative redundancy update. No text tokens are dropped.

## Inference details

On the initial pass, text queries include active nonvisual prompt/template
positions. Reference answers are never supplied to the inference selector.
Cache-off generation recomputes the prefix, so later passes can include tokens
already generated by the model. Do not describe this as an input-question-only
mask throughout generation. The depth diagnostic instead uses prompt-only passes.

Attention rows can be recomputed from native Q/K when fused kernels do not return
probabilities. Extraction and selection are not zero-cost. Preserve this overhead
in latency measurements. Qwen deep-stack visual paths and native position IDs
are handled by the retained compatibility backend.

## Why private historical names remain

`_vendor` retains the sequence-compaction machinery to avoid an unverified
backbone rewrite during release preparation. Initialization strings containing
`encoder_pmi` or `feature_diverse` are compatibility identifiers. The public
`runtime.install_policy` overrides initial selection with stable top-M and final
selection with text-only top-K. Unused diagnostic branches are not exposed as
public DeFT options. Unrecognized inherited `VISPRUNER_*` environment settings
are rejected instead of silently changing the method.
